Задача 3
Выберите подходящую систему управления виртуализацией для предложенного сценария. Опишите ваш выбор.

Сценарии:
100 виртуальных машин на базе Linux и Windows, общие задачи, нет особых требований. Преимущественно Windows based-инфраструктура, требуется реализация программных балансировщиков нагрузки, репликации данных и автоматизированного механизма создания резервных копий. - Microsoft Hyper-V 
Требуется наиболее производительное бесплатное open source-решение для виртуализации небольшой (20-30 серверов) инфраструктуры на базе Linux и Windows виртуальных машин. -  Proxmox Virtual Environment
Необходимо бесплатное, максимально совместимое и производительное решение для виртуализации Windows-инфраструктуры. - Microsoft Hyper-V Server
Необходимо рабочее окружение для тестирования программного продукта на нескольких дистрибутивах Linux. - KVM + virt-manager (VirtualBox)

Задача 4
Опишите возможные проблемы и недостатки гетерогенной среды виртуализации (использования нескольких систем управления виртуализацией одновременно) и что необходимо сделать для минимизации этих рисков и проблем. Если бы у вас был выбор, создавали бы вы гетерогенную среду или нет?

Проблем слишком много, от администрирования всех сред и хостов, до перерасхода средств на покупку лицензимй. Бэкапы, снапшоты и DRP для каждой системы, Монитринг по разным каналам создает дополнительную нагрузку плюс алертинг летит к чертям. Обновление и закрытие уязвимостей будет занимать намного больше времени чем следить за 1 средой.  

Для уменьшения проблем:
Единая абстракция: Внедрить Cloud Management Platform (например, VMware vRealize, OpenStack, или облачный портал) для унифицированного самообслуживания. Использовать Infrastructure as Code (Terraform, Ansible) с провайдерами для каждой платформы – это стандартизирует запуск ВМ независимо от бэкенда.
Унификация форматов: Хранить базовые образы ВМ в формате OVF/OVA для обеих систем. При необходимости конвертации использовать специализированные средства (StarWind V2V Converter, qemu-img) с обязательным тестированием после миграции.
Централизованное хранилище и сеть: Использовать общую SAN (FC/iSCSI) или NFS – тогда ВМ можно перемещать между хостами разных гипервизоров (при условии совместимости драйверов). Внедрить единую сетевую VLAN-модель и стандартные политики QoS.
Мониторинг и логирование: Настроить сбор метрик через единый агент (например, Telegraf) с экспортерами для разных гипервизоров, агрегировать в Prometheus + Grafana. Все логи стекать в центральный SIEM (Splunk, ELK) с нормализацией событий.
Резервное копирование: Выбрать кроссплатформенное решение для бэкапа (Veeam, Commvault, Acronis), поддерживающее все используемые гипервизоры. Регулярно тестировать восстановление ВМ на альтернативной платформе (в рамках DRP).
Организационные меры: Закрепить ответственного архитектора за всей виртуальной инфраструктурой. Разработать чёткий регламент выбора платформы под новый проект (критерии: стоимость, требуемая производительность, интеграция).Проводить кросс-тренинги команд, чтобы специалисты были взаимозаменяемы.
